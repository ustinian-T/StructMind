# StructMind Web 核心学习工作台设计规格

日期：2026-08-12

状态：待用户审阅

## 1. 设计目标

将浏览器 Web 端从传统侧栏仪表盘升级为以学习任务为中心的 AI 学习工作台。产品体验参考 ChatGPT 与 Gemini 的克制框架、连续对话和上下文能力，但不复制其品牌视觉；StructMind 必须保留正式题库、答案来源和导入审计的专业可信度。

本阶段只改造 `static/` 下的浏览器 Web 端，不修改 uni-app 页面。

完成后的界面应满足：

- 学生进入页面后能立即判断“接下来学什么”。
- 练习时题目始终是视觉中心，来源与进度清晰但不喧宾夺主。
- AI 导师像连续学习伙伴，而不是嵌在卡片里的普通客服聊天框。
- 学习数据被转化为可执行建议，而不是数字卡片墙。
- 正式题库答案、Word 作业答案和 AI 参考内容始终有明确来源区分。
- 桌面端与手机浏览器均可完成完整学习流程。

## 2. 设计原则

### 2.1 安静聚焦

使用暖灰白画布、深墨色文字和单一氧化青绿色强调色。取消品牌渐变、装饰性 emoji、大面积玻璃拟态和普遍悬浮阴影。层级主要依靠留白、字号、细分隔线和局部底色建立。

### 2.2 任务优先

首屏不再以欢迎横幅、功能入口或统计卡片为主，而是呈现一个清晰的下一步学习任务。界面中的每块信息都需要回答以下问题之一：现在做什么、为什么做、做得怎样、下一步是什么。

### 2.3 AI 可用但不越权

AI 可以解释、追问、检查思路和生成变式题，但不得把 AI 生成内容伪装成正式题库标准答案。所有 AI 产出必须显示来源类型。

### 2.4 长时阅读友好

题干、解析和导师回复的正文宽度控制在约 68–76 个中文字符以内。交互状态使用 160–220ms 过渡，并尊重 `prefers-reduced-motion`。

## 3. 信息架构

保留现有功能，不改变后端 API。Web 端一级导航调整为：

1. 学习台：今日任务、继续练习、学习建议与核心进度。
2. 题库：正式考试题库的顺序、随机和推荐练习。
3. 作业：Word 作业题与来源答案。
4. AI 导师：连续对话、概念解释、思路检查和变式题。
5. 复习：错题与待巩固知识点。
6. 更多：讨论题、导入审计、AI 配置和管理功能，按角色显示。

移动端使用四项底部导航：学习台、练习、AI 导师、我的。其余入口放入“更多”面板，不在底部堆叠。

## 4. 全局应用框架

### 4.1 桌面端

- 左侧轨道宽度约 232px，保持固定但视觉轻量。
- 顶部展示品牌、主导航和账户入口，不再重复显示每个页面的品牌名称。
- 主画布最大宽度约 1440px，根据场景切换单栏或双栏布局。
- 右侧上下文栏宽度约 296–320px，仅在练习、AI 导师或需要辅助信息时出现。
- `WS` 与 AI 配置状态不再使用两个抢眼的胶囊标签；合并为低干扰的“系统状态”入口，异常时才强调。

### 4.2 移动端

- 视口使用 `min-height: 100dvh`。
- 主内容单列显示，保留 16px 左右安全边距。
- 练习提交、下一题等关键动作固定在底部导航上方。
- 对话输入框跟随软键盘，并包含底部安全区。
- 不以抽屉侧栏作为主要导航；底部导航承担高频路径。

## 5. 设计系统

### 5.1 色彩

- 页面背景：暖灰白，不使用绿色渐变背景。
- 主表面：纯白或近白，仅对真正独立的工作区使用。
- 主文字：带绿色倾向的深墨色。
- 次级文字：统一冷静灰绿色。
- 强调色：单一氧化青绿，用于当前状态、主按钮和可交互文本。
- 成功、警告和错误色只表达语义，不作为装饰。

所有颜色通过 CSS 自定义属性管理，并提供通过 WCAG AA 对比度的焦点、禁用和错误状态。

### 5.2 字体与数字

- 中文正文优先使用系统中文无衬线字体，英文和数字使用 `Segoe UI Variable`/系统字体栈，不引入网络字体依赖。
- 标题采用 600–700 字重，避免所有信息都加粗。
- 数据、题号和进度使用等宽数字特性 `font-variant-numeric: tabular-nums`。
- 页面主标题约 28px，工作区标题 20–22px，正文 15–17px。

### 5.3 表面与组件

- 一级工作区圆角约 18px；内部选项、输入和按钮使用 10–12px；避免所有元素统一大圆角。
- 默认不使用阴影。仅浮动输入框、移动端固定操作栏和模态层使用轻微有色阴影。
- 胶囊样式只用于真实筛选或状态，不用于普通按钮和导航。
- emoji 不作为主要图标。沿用现有内联图标能力，统一 1.75px 左右描边。

## 6. 页面设计

### 6.1 学习台

未登录状态：

- 首屏展示简洁的产品说明和“登录后继续学习”入口。
- 同时保留题库规模与导入审计可信度，避免页面看起来只是 AI 营销页。
- 登录不是遮住所有内容的大卡片，学生仍可理解产品价值和题库来源。

已登录状态：

- 顶部主任务显示“继续上次练习”或基于薄弱项生成的推荐任务。
- 主任务包含题量、预计时长、来源与推荐原因，并只有一个主操作。
- 下方展示“今日计划”“待复习”和“最近进步”，最多三块，采用非等高布局。
- 题库总量与审计状态收进紧凑的可信度栏，不与学习任务争夺注意力。

### 6.2 题库练习

创建练习：

- 将题型、章节和题量合并成一条清晰的练习配置工作流。
- “顺序练习”作为主操作，“随机出题”和“智能推荐”为次操作。
- 实时说明当前筛选会得到多少道题，并明确数据来自正式题库。

答题工作区：

- 桌面端为题目主栏 + 右侧会话信息栏；手机端为单栏。
- 顶部依次显示章节、题型、题号和“正式题库”来源标识。
- 题干与选项占据主要空间；选项具有完整悬停、键盘焦点、选中和禁用状态。
- 主按钮使用“提交答案”，未选择答案时禁用并说明原因。
- 提交后在原位展示结果、标准答案、来源解析和错因提示。
- 下一题是结果区之后的主要动作；上一题、结束本组为低优先级操作。
- 右侧栏显示本组进度、正确率和题目导航，不重复展示无用统计。

### 6.3 AI 导师

- 页面采用单一连续对话画布，不把整个对话包在卡片中。
- 助手消息使用无气泡正文布局；用户消息使用轻量底色区分。
- 空状态只保留一句角色说明、四个与数据结构相关的真实示例和居中的复合输入框。
- 输入框支持多行、回车发送、Shift+Enter 换行，并展示明确发送按钮。
- 输入框上方提供四种学习意图：解释概念、检查思路、逐步提示、生成变式题。
- 每条 AI 回复显示“AI 导师”来源标签；引用正式题库时额外显示题目编号。
- 右侧上下文栏显示当前导师模式、会话主题与可用能力；没有上下文时隐藏。
- 流式回复使用文本光标或骨架行，不使用跳动 emoji。
- 服务失败以内联消息呈现，并提供重试，不让错误回复伪装成正常导师消息。

### 6.4 作业与讨论题

- 沿用题目工作区结构，明确标注“Word 作业答案”或“AI 参考批改”。
- AI 评分、来源答案和学生作答分成三个独立区块。
- 讨论题的反馈以可阅读的批注结构呈现，不只给单一分数。

### 6.5 复习与错题本

- 默认按薄弱知识点组织，不以无差别列表开始。
- 每组显示错题数量、最近错误日期和建议复习动作。
- 支持单题重做和“开始本组复习”，避免同时出现过多同级按钮。

### 6.6 学习画像

- 首页仅展示驱动行动的摘要；完整画像使用独立视图。
- 主要内容为下一步建议、章节掌握度趋势和最近练习记录。
- 不保留重复的总练习、答对、正确率和连续天数卡片墙。
- 数据不足时显示如何开始积累画像的具体空状态。

### 6.7 导入审计、AI 配置与管理

- 保留全部功能，不进行功能删减。
- 审计表提供粘性表头、问题类型筛选和处理状态区分。
- AI 配置采用分组表单和内联验证，密钥状态明确但不泄露值。
- 管理页面使用紧凑列表，不套用学习页面的卡片风格。

## 7. 核心交互与状态

必须覆盖以下状态：

- 应用初始加载：与页面骨架形状一致的加载占位。
- API 失败：页面级错误说明、重试操作和不丢失当前输入。
- 空数据：解释为什么为空以及下一步怎么做。
- 未登录：保留可理解的产品内容，清楚标注需要登录的操作。
- AI 未配置：导师页面说明缺少配置，并提供直接入口。
- 正在提交答案：锁定重复提交，保留已选答案。
- 键盘导航：所有按钮、选项、输入和导航具有可见焦点。
- 减少动态效果：关闭位移、缩放和持续动画，仅保留必要状态切换。

## 8. 数据与功能边界

- 继续使用现有 `/api/*` 接口和前端状态模型。
- 不修改题库、答案判定、AI 提示词或权限规则。
- 不修改 uni-app、uniCloud 页面和移动原生壳。
- 不添加新的前端框架或构建依赖；在现有 Vanilla JS + CSS 架构中实施。
- 可以重组 `static/app.js` 中的渲染函数和 `static/styles.css` 中的设计令牌，但不得破坏现有 API 调用与事件处理。

## 9. 可访问性和内容要求

- 所有交互目标最小为 44×44px，紧凑桌面表格操作除外。
- 使用语义化的 `nav`、`main`、`section`、`aside`、`button`、`label` 与表格结构。
- 页面提供“跳到主要内容”链接。
- 图标按钮必须有可访问名称。
- 表单错误与状态变化使用可感知的文本，而非只依赖颜色。
- 所有成功文案不使用感叹号；错误文案直接说明问题和恢复方式。
- 页面内容使用自然、具体的中文，不使用泛化 AI 营销话术。

## 10. 验收标准

### 10.1 功能

- 现有 Web 一级功能均可进入：学习台、题库、作业、AI 导师、讨论、错题、AI 配置、导入审计与管理。
- 登录、创建练习、答题提交、上一题/下一题、AI 对话、错题重做和配置保存事件仍绑定有效。
- 正式答案与 AI 内容的来源标识在相应页面可见。

### 10.2 视觉与交互

- 1440×900 下主学习区层级清晰，无大面积空洞卡片墙。
- 390×844 下无水平溢出，底部导航、固定操作与系统安全区互不遮挡。
- 练习题干在桌面与手机上均为页面主要视觉元素。
- AI 导师采用连续阅读布局，空状态与有消息状态均完整。
- 页面不再使用大面积绿色渐变、装饰 emoji 或通用玻璃卡片作为主要视觉语言。

### 10.3 质量

- 现有 Python 与前端回归测试通过。
- 浏览器控制台没有新增未捕获异常。
- 使用 Playwright 分别验收学习台、创建练习、答题、AI 导师、审计页面的桌面截图，以及学习台、答题和 AI 导师的手机截图。
- 检查键盘焦点、空状态、API 错误状态和 `prefers-reduced-motion`。

## 11. 实施顺序

1. 重建 CSS 设计令牌、排版、焦点状态与全局应用框架。
2. 重构学习台，将统计卡片墙转换成任务导向布局。
3. 重构练习创建和答题工作区，完成来源标识与结果状态。
4. 重构 AI 导师连续对话、输入框和错误/流式状态。
5. 统一作业、讨论、错题、配置、审计和管理页面。
6. 完成移动端底部导航、固定操作与响应式布局。
7. 运行自动化测试和桌面/手机浏览器验收，根据截图修整。

## 12. 明确不做

- 本阶段不修改 uni-app 页面。
- 不新增后端能力或数据库字段。
- 不更换 StructMind 品牌名称和 Logo。
- 不照搬 ChatGPT、Gemini 的商标、图标或布局细节。
- 不为了视觉效果增加与学习状态无关的动画、排行榜游戏化或营销区块。
